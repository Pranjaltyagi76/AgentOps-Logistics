## 0. Live deployment (2026-11-16)

| Part | Where | Notes |
|---|---|---|
| Frontend | https://agentops-logistics.vercel.app | Vercel Hobby, project `agentops-logistics`, root `frontend`, preset Vite (from `frontend/vercel.json`) |
| Backend | https://agentops-api-pehy.onrender.com | Render free web service `agentops-api` (Docker, Singapore), from the `render.yaml` Blueprint `agentops-logistics` |
| Database | Neon project `agentops-logistics` | Postgres 16, AWS ap-southeast-1 (Singapore), database `agentops`, role `agentops_owner` |

- Deploys: pushing to `main` redeploys both. Render waits for GitHub checks (`autoDeployTrigger: checksPass`),
  except that a change to `render.yaml` syncs the Blueprint, which deploys at once. Vercel skips a deployment
  when nothing under `frontend/` changed.
- Secrets live only in the Render dashboard (`DATABASE_URL`, `MIGRATION_DATABASE_URL`, `GEMINI_API_KEY`,
  `OWNER_EMAIL`; `JWT_SECRET` generated by Render). `OWNER_PASSWORD` was set for the first boot only and then
  deleted. Vercel holds one non-secret value, `VITE_API_BASE_URL`.
- Measured on the live service: first build plus boot about 5 min; a woken instance answered after 63 s while
  seeding ran before the server (now in the background, see §5); rule-based runs 0.3–1.6 s (p95 1.4 s over 31,
  0.08 s locally); no restarts or out-of-memory events during deploys and a 31-run suite (Render shows no
  memory metrics on the free plan).

## 2. Local development

### 2.1 Prerequisites (one-time, Windows 11 Home)

Run in an **Administrator PowerShell** (the user does this; it changes Windows features and needs a reboot):

```bash
wsl --install
```

Reboot, then:

```bash
winget install -e --id Docker.DockerDesktop
```

Start Docker Desktop once and accept its setup. Verify:

```bash
docker compose version
```

**Fallbacks without Docker:**
- **Neon:** create a free project, make a `dev` branch, and put its connection string in `backend/.env` as `DATABASE_URL`.
- **Portable Postgres binaries** (what the dev machine uses as of 2026-11-08, no admin rights needed):
  Postgres 16.2 binaries in `%LOCALAPPDATA%\Programs\pgsql-16`, data in `%LOCALAPPDATA%\agentops-pg\data`,
  listening on `127.0.0.1:5432` with the same user/password/database names as the Docker setup, plus an
  empty `agentops_test` database for tests. It does not start by itself after a reboot; start it with
  (safe to re-run, does nothing if it is already running):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_db.ps1
```

  To start it automatically at sign-in, register the per-user scheduled task shown in the header of
  `scripts/start_db.ps1` (no admin rights needed).

### 2.1a Generated API types

`frontend/src/lib/api-schema.ts` is generated from the backend's OpenAPI schema; CI fails if either is stale.
After changing an API model:

```powershell
cd backend; uv run python ..\scripts\export_openapi.py      # writes frontend/openapi.json
cd ..\frontend; npm ci --prefix tools/openapi; npm run gen:api
```

The generator lives in its own package (`frontend/tools/openapi`) because openapi-typescript needs TypeScript 5
and the app uses TypeScript 7. New code should import types from `@/lib/api-schema`
(`components['schemas']['...']`); the older hand-written types are migrated as their screens change.

### 2.2 Run locally (available from Phase 0)

```bash
docker compose up -d db
```

Backend (PowerShell, from the repo root). Python dependencies are managed by **uv**: `uv sync`
creates `backend/.venv` from the exact versions in `backend/uv.lock`.

```powershell
cd backend
uv sync
Copy-Item .env.example .env     # then edit values; add GEMINI_API_KEY yourself (Phase 6)
uv run alembic upgrade head
uv run python ..\scripts\seed_db.py         # loads data/scenarios (safe to re-run)
uv run python ..\scripts\seed_demo.py       # optional: labelled demo suite runs (rule-based, no LLM)
uv run python ..\scripts\embed_sops.py      # optional: SOP embeddings for SOP_RETRIEVAL=hybrid (1 request)
uv run python ..\scripts\create_owner.py    # reads OWNER_EMAIL / OWNER_PASSWORD from env or .env
uv run uvicorn app.main:app --reload --port 8000
```

To add a dependency: `uv add <package>` (or `uv add --dev <package>`), then commit `pyproject.toml` and `uv.lock`.

Frontend (second terminal, from the repo root):

```powershell
cd frontend
npm install
Copy-Item .env.example .env.local  # VITE_API_BASE_URL=http://localhost:8000
npm run dev                     # http://localhost:5173
```

### 2.3 Local database

[../docker-compose.yml](../docker-compose.yml) runs `pgvector/pgvector:pg16` as `agentops-db` on port 5432
(user `agentops`, password `agentops_dev`, database `agentops`, for local use only) with a named volume
and a `pg_isready` healthcheck. The default `DATABASE_URL` points at `127.0.0.1` rather than
`localhost`, so a missing database fails fast instead of timing out on IPv6 first.

## 4. Database (Neon)

1. Create project `agentops-logistics` (Postgres 16 to match CI; the region nearest the Render region; it
   cannot be changed later). Free plan on 2026-11-16: 1 GB storage per project, 100 CU-hours per month,
   compute suspends after 5 minutes idle.
2. The `vector` extension is created by Alembic migration `0009` (Phase 10); it worked on Neon unchanged.
3. Copy two connection strings from **Connect to branch** → *Connection string*, with **Connection pooling**
   ON (`-pooler` host → `DATABASE_URL`) and OFF (direct → `MIGRATION_DATABASE_URL`). Paste them as shown
   (`postgresql://…?sslmode=require&channel_binding=require`): the settings point both at psycopg 3.
4. SQLAlchemy engine: `pool_pre_ping=True`, small pool (`pool_size=3`, `max_overflow=2`), `pool_recycle=300`.
5. Trace retention is documented in [system_design.md §11](system_design.md) but not built: on 2026-11-18 the
   database was 11 MB (65 runs, ~12 KB of trace each), about 1 % of the free tier.

## 5. Backend (Render)

Deployed from the Blueprint [`render.yaml`](../render.yaml): **New → Blueprint**, pick the repository, fill in
the `sync: false` values, deploy. Render free web services: 0.1 CPU (the dashboard shows a 0.15 limit),
512 MB, sleep after 15 minutes without traffic, about a minute to wake, 750 instance hours per workspace and
month, **no shell and no one-off jobs**.

- Image: [`backend/Dockerfile`](../backend/Dockerfile), built from the repository root so `data/` and
  `scripts/` ship with it; dependencies exactly from `uv.lock`, no dev tools, non-root user.
- Start: [`backend/start.sh`](../backend/start.sh) runs `alembic upgrade head`, starts uvicorn, and in the
  background runs `seed_db.py`, `seed_demo.py` (unless `SEED_DEMO_ON_START=false`) and, only while
  `OWNER_PASSWORD` is set, `create_owner.py`. All are idempotent; on later boots they report "unchanged".
  Set `OWNER_PASSWORD` for the first deploy, then delete it in **Environment** (the owner stays).
- Health check `/api/v1/health`; `/api/v1/version` reports `RENDER_GIT_COMMIT`.
- Client IP for the login rate limit (`app/core/limits.py`): measured on Render, `X-Forwarded-For` arrives
  as `[client-sent…, client, proxy, proxy]` and Cloudflare's `CF-Connecting-IP` holds the client, so
  `CLIENT_IP_HEADER=cf-connecting-ip` with `TRUSTED_PROXY_HOPS=3` as the fallback. With 1 hop (first
  guess) a spoofed header escaped the limit; the smoke test's `--check-login-limit` now shows 10 × 401
  then 429. uvicorn runs with `--no-proxy-headers`.
- Hybrid SOP retrieval is off (`SOP_RETRIEVAL=lexical`); to use it, set `hybrid` and run
  `scripts/embed_sops.py` locally against Neon (one embedding request).

**Free-tier consequences:** the frontend shows a "waking up backend…" banner and retries; runs in flight when
the instance sleeps are marked `errored(orphaned)` at the next start; no heavy local ML libraries; no
keep-alive pinging to defeat sleep.

## 6. Frontend (Vercel)

1. **Add New → Project**, import the repository. Vercel's GitHub app must be allowed to see it (**Adjust
   GitHub App Permissions**; a popup the user approves). Vercel detects both apps in the repository: choose
   root directory `frontend`; the Vite preset, `npm run build` and `dist` come from
   [`frontend/vercel.json`](../frontend/vercel.json), which also adds the SPA rewrite, `nosniff`,
   `Referrer-Policy`, `X-Frame-Options: DENY` and immutable caching for `/assets/*`.
2. Environment variable `VITE_API_BASE_URL` = the Render URL, type **Config** (it is public: it ends up in the
   bundle), environment Production.
3. Deploy. If the project exists without a production deployment (e.g. an interrupted import),
   **Deployments → ⋯ → Create Deployment → `main` → Deploy to Production**.
4. The project name `agentops-logistics` gave `https://agentops-logistics.vercel.app`, which was already set
   as `CORS_ORIGINS` on Render; with another URL, update `CORS_ORIGINS` and redeploy the backend.

## 7. CI/CD

- GitHub Actions on push/PR: backend (ruff, OpenAPI check, scenario validation, migrations, pytest with
  `pgvector/pgvector:pg16`, seed twice), frontend (generated types check, oxlint, `tsc -b`, vitest, build),
  and **Docker** (build the image from the repository root, check it holds no `.env`, boot it against
  Postgres, wait for seeding, run `scripts/smoke_test.py`, restart the container and check the run, trace and
  score persisted, print memory use).
- Render deploys `main` after the checks pass; Vercel deploys on every push that touches `frontend/`.
- No secrets in CI; LLM tests are skipped.

## 8. Smoke test (after each deploy)

[`scripts/smoke_test.py`](../scripts/smoke_test.py) (standard library only) covers deployment.md §8:

```bash
python scripts/smoke_test.py --api https://agentops-api-pehy.onrender.com --frontend https://agentops-logistics.vercel.app --expect-sha <commit> --check-login-limit
```

It waits for a sleeping backend, then checks health and database, the version SHA, demo login, the scenario
count, one `rule-based-v1` run end to end (verdict, score, trace), CORS for the frontend and against a foreign
origin, the frontend and a deep link, and scans the bundle for secret values. `--after-restart <run_id>` checks
a run survived a restart; `--check-login-limit` locks owner sign-in from your IP for a minute;
`--gemini` signs in as owner (`OWNER_EMAIL`/`OWNER_PASSWORD` from the environment) and runs one Gemini run
(about 4 of the free tier's 20 daily requests).

## 10. Rollback and operations

- Vercel: promote the previous deployment.
- Render: redeploy the previous commit. Migrations are additive, so older code tolerates the newer schema; never ship a destructive migration together with code that needs it.
- Neon: point-in-time restore / branch from a past timestamp if data is damaged (verify retention window on free tier).
- Rotate `GEMINI_API_KEY` / `JWT_SECRET` in Render env; rotating `JWT_SECRET` logs everyone out.
- Watch Gemini usage in AI Studio and the `usage_counters` table.
